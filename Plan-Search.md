# План доработки страницы «Поиск»

## 1. UX

### 1.1 Ввод города
- [x] Заменить выпадающий список на **Input + autocomplete** со строгим выбором из предложенных значений (Paris, Barcelona, Madrid)
- [x] При вводе первой буквы показывать подсказку: «Сейчас в системе рассматриваются только три города: Мадрид, Барселона и Париж»
- [x] Значение можно выбрать только из списка (не произвольный ввод)

### 1.2 Валидация дат
- [ ] Выезд должен быть позже заезда
- [ ] Дата заезда не может быть в прошлом
- [ ] Понятные сообщения об ошибках

### 1.3 Блок профиля
- [ ] Краткий блок «Поиск с учётом ваших требований» при наличии профиля (тип поездки, бюджет, ключевые предпочтения)

### 1.4 Проверить гостиницу
- [ ] Добавить поле **«Проверить гостиницу»** — ввод названия отеля пользователем
- [ ] По названию выполняется оценка гостиницы по профилю пользователя
- [ ] Выдаётся карточка отеля — пользователь видит, насколько понравившаяся гостиница соответствует его требованиям

## 2. Карточки отелей

### 2.1 Итоговая оценка
- [ ] Добавить **final_score** в карточку (сейчас отображаются quality и value, но не итоговый score)
- [ ] Выделить final_score как главный показатель рекомендации

### 2.2 Дополнительные метрики
- [ ] Отображать **consistency_score** (согласованность отзывов), если актуально

### 2.3 Сортировка
- [ ] Сортировка результатов: по цене, по final_score, по рейтингу

### 2.4 Чекбокс «Мой выбор»
- [ ] В карточке отеля добавить чекбокс **«Мой выбор»**
- [ ] Тултип: «Эта информация будет использована ИИ в будущем для оценки отелей в других поездках»
- [ ] Сохранение выбора (localStorage / API) для последующего использования AI

### 2.5 Сохранение карточки
- [ ] Возможность сохранить карточку отеля в виде **md-файла**
- [ ] Кнопка «Скачать карточку» → формирование и скачивание .md с данными отеля
